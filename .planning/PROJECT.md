# Portfolio & Blog Modernization

## What This Is

A complete visual and UX transformation of Roméo Martinez's portfolio and blog site. The site maintains its signature interactive business card but gains a bold, modern design system with strong visual identity, refined typography, and an immersive storytelling-focused blog experience inspired by Rudeops' clean content presentation, Zeroday's structured layout, and Peggy Gou's distinctive visual personality.

## Core Value

The blog reading experience must feel immersive and narrative-driven — each post should guide readers through content with visual chapter breaks, refined typography, and deliberate pacing that makes technical DevOps content engaging and memorable.

## Context

**Current State:**
- Portfolio uses a creative flippable business card concept (front: intro, back: skills)
- Blog has 6 technical DevOps posts with good content but basic presentation
- Typography is functional but lacks hierarchy and visual distinction
- Blog posts are well-structured HTML with semantic sections
- No search, filtering, or discovery features
- Green accent color exists but palette lacks depth

**Inspiration Sites Analyzed:**
- **Rudeops** (rudeops.com): Clean newsletter-style blog with clear typography, tag system, publication dates, and simple but effective content hierarchy
- **Zeroday** (zerodaycyberacademy.substack.com): Structured Substack blog with strong content organization, clear post cards, and effective use of metadata
- **Peggy Gou** (peggygou.com): Distinctive visual identity with bold typography, immersive full-screen sections, deliberate transitions, and strong personality

**User Intent:**
- Keep the flippable card identity (core interaction stays)
- Transform blog from "basic content display" to "immersive reading experience"
- Create visual boldness without sacrificing technical credibility
- Make DevOps content engaging through storytelling structure

## Constraints

- **Tech Stack**: Static HTML/CSS/JS only — no build tools, no frameworks, GitHub Pages compatible
- **Timeline**: Fully deployed and live
- **Browser Support**: Modern browsers only (CSS Grid, Flexbox, modern JS APIs assumed)
- **Hosting**: GitHub Pages static hosting — no backend capabilities
- **Maintenance**: Single author managing content — keep workflow simple
- **Content**: Existing blog posts should work with new design without requiring rewrites
