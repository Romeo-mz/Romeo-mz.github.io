Monitoring Kubernetes Clusters with k9s

Jan 7, 2026 · Kubernetes · 4 min read

As a DevOps engineer who's recently incorporated k9s into my workflow, I've found it to be a game-changer for Kubernetes cluster monitoring. This terminal-based UI transforms the often cumbersome kubectl commands into an intuitive, real-time interface that makes overseeing complex deployments feel almost effortless. In this post, I'll walk you through how I use k9s daily to keep my clusters running smoothly.

1. Getting started with k9s

Before diving in, ensure you have kubectl configured and access to your Kubernetes cluster. Installing k9s is straightforward: use your package manager like brew install k9s on macOS or choco install k9s on Windows, or grab the latest release from GitHub. Once installed, simply type k9s in your terminal. It automatically picks up your kubeconfig and connects to the current context, presenting you with a sleek, curses-based interface that feels right at home in the terminal.

2. Key monitoring features that shine

k9s excels in providing live, interactive views of your cluster's resources. The main dashboard shows a pulse of your cluster's health, with color-coded statuses for quick visual assessment. Navigate between resource types using single-key shortcuts: p for pods, d for deployments, s for services, n for nodes. Each view updates in real-time, allowing you to spot issues instantly.

For deeper inspection, press l to view logs, d again to describe a resource, or e to exec into a container. The interface even supports fuzzy searching and filtering, making it easy to zero in on specific resources amidst a sea of microservices. Check out the full command reference for more shortcuts.

3. A typical monitoring session

My day usually starts with firing up k9s to get a bird's-eye view of cluster health. I begin by checking the pulse view for any immediate red flags—failing pods or high resource usage.

If everything looks green, I dive into the pods view to scan for restarts or pending states. When I spot an issue, like a pod in CrashLoopBackOff, I press l to tail the logs in real-time, often revealing configuration errors or resource constraints.

From there, I might exec into the container with e to run diagnostic commands, or switch to the deployments view to check rollout status. If needed, I scale resources or trigger rollbacks directly from k9s. Throughout, the interface's responsiveness keeps me focused, turning what used to be a series of kubectl commands into a fluid, keyboard-driven workflow.

Summary: k9s has quickly become indispensable in my DevOps arsenal, blending the power of kubectl with the immediacy of a modern UI. Its real-time updates and intuitive shortcuts have cut my monitoring time in half, letting me respond to issues before they escalate. If you're managing Kubernetes clusters, give k9s a try—you might never go back to plain kubectl for monitoring.
