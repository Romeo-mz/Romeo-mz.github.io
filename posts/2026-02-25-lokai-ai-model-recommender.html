Lokai: A CLI That Recommends AI Models Based on Your Hardware

Feb 25, 2026 · Go · AI · Open Source · 6 min read

The local AI space has exploded. Between Ollama, LM Studio, and a growing catalog of quantized models, there are now hundreds of viable options for running inference on a personal machine. The problem is that choosing the right model is genuinely painful.

You need to know your available VRAM, understand what quantization levels fit in memory, and then map that against use case requirements — do you need speed for code completion, or quality for long-form reasoning? Most people either run into OOM errors after blindly downloading a model, or they default to whatever the latest Reddit thread recommends regardless of their hardware.

I built Lokai to solve exactly this. It is a Go CLI that detects your hardware, asks what you want to do, and recommends the best local AI models from a curated catalog — then installs them via Ollama in one step.

The core problem: model selection friction

When you want to run a model locally, the path looks roughly like this: figure out your GPU VRAM, find a model that fits, check whether the quantization level is acceptable for your use case, install Ollama if you haven't, then run ollama pull. Each step has friction. The VRAM math is non-obvious. The relationship between quantization and quality is opaque. And the catalog of available models changes fast.

Lokai collapses all of this into a single guided flow. Run lokai, answer a few questions, pick from a ranked list, done.

How hardware detection works

The first thing Lokai does is detect your hardware. It uses three different strategies depending on the platform:

  • NVIDIA GPUs: Lokai uses the NVML library (via go-nvml) to query VRAM directly. This gives exact available memory, not just total VRAM.
  • Apple Silicon: Uses sysctl hw.memsize to read the total unified memory, then reserves 4 GB for the OS. The rest is treated as usable VRAM since M-series chips share memory between CPU and GPU.
  • CPU-only or unknown GPU: Falls back to 70% of available system RAM as a conservative estimate for what can be used for inference.

From there, the detected VRAM gets mapped to one of five hardware tiers: Edge (<4 GB), Low-end (4–8 GB), Consumer (8–16 GB), Mid-range (16–40 GB), and High-end (≥40 GB). Models in the catalog are tagged with the minimum tier they require, so the recommendation engine can filter immediately.

You can check what Lokai detects about your machine without doing anything else:

lokai --scan-only

This outputs a table with your OS, CPU, total RAM, GPU model, available VRAM, and the resulting tier classification. No Ollama required at this step.

The model catalog

The catalog is the heart of Lokai. It currently holds 100+ hand-curated models across 9 use cases:

  • Chat (18 models) — conversational assistants
  • Code (13 models) — completion, refactoring, generation
  • Vision (10 models) — image understanding and captioning
  • Reasoning (7 models) — chain-of-thought, logic, math
  • Embedding (5 models) — vector representations for RAG or search
  • Image Generation (6 models) — Stable Diffusion and FLUX via ComfyUI
  • Video Generation (5 models) — short video synthesis
  • Audio (6 models) — speech-to-text via whisper.cpp, TTS via Piper
  • Uncensored (6 models) — uncensored models for research or creative use

Each entry in the catalog includes the Ollama tag, the exact VRAM requirement, quality and speed ratings, and whether the model can be pulled directly via Ollama or requires an external pipeline (like ComfyUI for image generation). The catalog also supplements itself dynamically by querying the Ollama Registry API with a 24-hour TTL cache, so new community models surface automatically without needing to update the binary.

The recommendation engine

After hardware detection, Lokai runs a questionnaire. It asks for your use case, optionally a sub-task (e.g., "code review" within the code category), and your priority — speed, balanced, or quality. If you have models already installed, it also asks whether you want to prefer remote models you're already running.

The engine then scores every eligible model against your inputs. Hardware compatibility is a hard filter: models that don't fit in your VRAM are excluded entirely. From the remaining candidates, scores account for priority alignment (speed-optimized models score higher if you picked "speed"), quality ratings, VRAM efficiency, and any cached benchmark data from previous runs.

Results are displayed in a TUI table built with Charmbracelet/bubbletea and lipgloss, showing rank, model name, VRAM needed, estimated tokens per second, and a quality rating. If you've previously benchmarked models on your machine, measured values replace estimates and are marked with a ✓ prefix. Estimated values show as ~X tok/s with a tilde.

Installation and cleanup

Once you select a model from the TUI, Lokai gives you two options: download it now via Ollama, or show manual installation instructions. For standard Ollama models, the download triggers ollama pull <tag> through the Ollama REST API with a live progress bar. For external pipelines (ComfyUI, whisper.cpp, Piper), Lokai displays step-by-step setup instructions instead since those can't be automated the same way.

Cleanup is equally simple:

lokai --clean

This removes all Ollama models currently installed. Useful if you've been experimenting and want a clean slate.

Non-interactive mode for automation

For CI/CD pipelines or automated environment setup, Lokai has a JSON output mode:

lokai --json --use-case code --priority speed

This outputs structured JSON with the hardware detection results and the full ranked recommendation list. Each recommendation includes the Ollama tag, VRAM requirement, quality, score, and estimated performance. You can pipe this into jq to extract the top model tag and automate the install step:

lokai --json --use-case chat | jq -r '.recommendations[0].ollama_tag' | xargs ollama pull

Benchmarking for accurate recommendations

VRAM requirements and speed estimates in the catalog are based on standard hardware profiles. But actual performance varies significantly depending on your CPU, RAM speed, and thermal state. Lokai solves this with a built-in benchmarking mode:

lokai --benchmark

This generates test prompts for each installed model, measures real tokens per second, and caches the results with a 6-hour TTL. In subsequent interactive sessions, if Lokai detects installed models without benchmark data, it offers to run a quick speed test before showing recommendations. Once benchmarks exist, the TUI shows measured values instead of estimates, making comparisons much more reliable.

Architecture notes

Lokai follows a strict layered architecture with no circular dependencies: CLI entry point → Presentation (TUI/UI) → Domain Logic (recommendation engine, catalog) → Hardware Detection → Ollama Integration. This makes the core logic testable in isolation and keeps the CLI layer thin.

The project requires CGO for the NVML integration on Linux/Windows (NVIDIA GPU detection). Cross-compilation is handled via Docker Compose in the dev environment, and GitHub Actions takes care of multi-platform releases. If CGO is unavailable or NVML isn't present, the code falls back gracefully to the CPU/RAM-based estimation.

Where this goes next

The catalog is the main thing I keep updating. Adding new models is low-friction — each entry is a struct with well-defined fields. The bigger open questions are around multi-GPU setups (current detection treats GPUs independently), better sub-task granularity within use cases, and possibly a homebrew tap for easier macOS installation.

The repo is at github.com/Romeo-mz/lokai. Contributions and catalog additions are welcome — the bar to add a model is intentionally low if you've tested it and have VRAM requirements handy.
