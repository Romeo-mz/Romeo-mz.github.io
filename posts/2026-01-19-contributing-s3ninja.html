Contributing to S3Ninja: Adding Presigned POST Support

Jan 19, 2026 · Open Source · AWS · DevOps · 4 min read

In the fast-paced world of DevOps, open source contributions can make the difference between a smooth development workflow and constant workarounds. As someone who builds and maintains cloud-native applications, I recently contributed to S3Ninja by adding support for presigned POST operations. This wasn't just a feature addition—it was about enabling more secure and efficient file uploads for our entire team.

What is S3 Ninja?

S3 Ninja is an open-source lightweight Docker container that emulates the Amazon S3 API for development and testing purposes. It supports only object methods such as GET, PUT, HEAD, DELETE. ACLs are also ignored but for non-public buckets.

It also has support for authorization for private buckets and provides a verified authorization hash that can be used to demonstrate "real" user credentials.

The Challenge

Our team was using S3Ninja extensively for local development and testing of S3 integrations. However, a critical gap existed: the lack of presigned POST support. In AWS S3, presigned POST allows clients to upload files directly to S3 without routing them through our backend servers. This is crucial for performance and security, but S3Ninja didn't support it, forcing us to either mock the functionality or use workarounds that compromised our testing accuracy.

Why Presigned POST Matters

Presigned POST operations are a game-changer for modern web applications. Instead of files passing through our backend—consuming bandwidth, processing power, and introducing potential security risks—they go directly from the client to S3. This approach:

  • Reduces server load and improves application performance
  • Enhances security by minimizing data exposure to backend systems
  • Enables larger file uploads without backend timeouts
  • Supports better user experiences with progress tracking

For our team, this meant more realistic testing environments and the ability to develop features that rely on direct S3 uploads without production compromises.

The Implementation

I implemented presigned POST support by studying AWS S3's specification and integrating the necessary components into S3Ninja. The key aspects included:

  • Policy document parsing and validation
  • Signature verification against access keys
  • Form field handling and condition enforcement
  • Seamless integration with existing upload mechanisms

The changes were designed to be backward-compatible, ensuring existing S3Ninja users wouldn't face disruptions while gaining new capabilities.

The Impact

This contribution has bridged a significant gap in S3Ninja's AWS S3 compatibility. For our team, it means more accurate local testing and the ability to develop direct upload features without architectural compromises. In the broader open source community, it provides developers with a more complete S3 emulation tool, reducing the friction of cloud-native development.

Contributing to S3Ninja wasn't just about adding a feature—it was about improving the tools that power countless development workflows. In DevOps, these small enhancements compound into significant productivity gains.
